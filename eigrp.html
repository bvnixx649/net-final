EIGRP

ข้อสอบจะให้รูป router ตัวหนึ่งที่ไปปลายทางเดียวกันได้หลายทาง (3, 4 ทางหรือมากกว่า) พร้อมตัวเลข แล้วถามว่าทางไหนคือ [[successor]], ทางไหนคือ [[fs|feasible successor]] และ [[fd|feasible distance]] เท่าไร ตอบเป็น IP ของ router ถัดไป, พอร์ตขาออก หรือเขียนเป็นประโยคก็ได้

EIGRP อยู่ตรงไหนในโลก routingAdvanced distance vector + DUAL

[[eigrp]] เรียนเส้นทางจากเพื่อนบ้านแบบ [[dv|distance vector]] แต่เก็บทุกทางที่เพื่อนบ้านบอกไว้ใน [[topotbl]] ด้วย จึงเป็นลูกผสมที่ค่อนไปทาง distance vector และมีทางสำรองพร้อมใช้ตลอด

อาจารย์ให้รู้ว่าแต่ละโปรโตคอลใช้ metric อะไร แตะแต่ละตัวบนเส้นด้านล่างเพื่อเทียบกัน

EIGRP เก็บข้อมูลไว้สามตาราง [[nbrtbl]] บอกว่าใครเป็นเพื่อนบ้าน [[topotbl]] เก็บทุกทางที่เพื่อนบ้านบอกมา แล้ว [[dual]] เลือกทางที่ดีที่สุดใส่ [[rtbl]] ภาพนี้คือ router R จากรูปด้านบน

ตัวเลข metric มาจากไหน

[[metric]] คือตัวเลขทุกตัวในบทนี้ สูตรเต็มในสไลด์หน้าตาแบบนี้ แตะแต่ละตัวเพื่อดูความหมาย

ค่าเริ่มต้นของ [[kval|ค่า K]] ปิด load กับ reliability ไว้ สูตรที่ใช้จริงจึงเหลือแค่ bandwidth กับ delay

ข้อสอบจะให้ตัวเลข metric มาเลย ไม่ต้องคิดสูตรนี้เอง แต่ลองกดดูว่าตัวเลขในสไลด์มาจากไหน จะเห็นว่าลิงก์ที่ช้าที่สุดเส้นเดียวทำให้ทั้งเส้นทางแย่

ระยะสองท่อน: FD กับ RDFeasible Distance = cost + Reported Distance

ทุกเส้นทางแบ่งเป็นสองท่อน ท่อนแรกจากเราถึงเพื่อนบ้านคือ [[cost]] ท่อนที่สองจากเพื่อนบ้านถึงปลายทางคือ [[rd]] ซึ่งเพื่อนบ้านบอกเรามา ผลรวมทั้งเส้นคือ [[fd]]

RD เป็นตัวเลขที่เพื่อนบ้านคิดมาให้ เราไม่ต้องคิดเอง ในข้อสอบโจทย์จะให้มาเลย แตะแต่ละทางเพื่อดูว่าสองท่อนรวมกันเป็น FD อย่างไร

เลือกทางหลัก แล้วเช็คทางสำรองSuccessor, feasibility condition, feasible successor

[[successor]] คือทางที่ FD ต่ำที่สุด ส่วนทางอื่นจะเป็น [[fs|feasible successor]] (FS) ได้ก็ต่อเมื่อ RD ของมัน น้อยกว่า FD ของ successor

กฎนี้ชื่อ [[fc]] จุดที่คนพลาดบ่อยคือเอา FD ของทางนั้นมาเทียบ ที่ถูกคือดู RD ของทางนั้น เทียบกับ FD ของ successor ตัวเดียว

ทำไมต้องเป็น RD? ถ้าเพื่อนบ้านบอกว่าตัวเองอยู่ห่างปลายทางน้อยกว่าทางที่ดีที่สุดของเรา แปลว่าทางของมันไม่ได้วิ่งผ่านเราแน่นอน (ถ้าผ่านเรา ระยะของมันต้องมากกว่าระยะของเรา) จึงส่งให้มันได้โดยไม่เกิด [[loop]] ลองลากตัวเลขของทาง C ดู แล้วดูว่าสถานะของทุกทางเปลี่ยนอย่างไร

ตัวอย่างสามเหลี่ยมในสไลด์R2 → 192.168.1.0/24 (Routing-2, p20–22)

R2 ไป 192.168.1.0/24 ได้สองทาง: ผ่าน R3 ตรงๆ หรืออ้อมผ่าน R1 ทางผ่าน R3 มี FD ต่ำกว่าจึงเป็น successor และ R1 เป็น FS เพราะ RD ของ R1 (2,170,112) น้อยกว่า FD ของ successor (3,012,096)

ลากแถบด้านล่างทีละขั้น ตัวเลขทุกตัวตรงกับ show ip eigrp topology ในสไลด์

ถ้า successor ล่มDUAL: promote the FS, or go active and query

ถ้ามี FS อยู่แล้ว [[dual]] ยก FS ขึ้นเป็น successor ใหม่ทันทีโดยไม่ต้องคำนวณหรือถามใคร ถ้าไม่มี FS router ต้องเข้า [[active]] แล้วส่ง query ถามเพื่อนบ้านก่อน

นี่คือเหตุผลที่ EIGRP [[conv|converge]] เร็ว ลองตัดลิงก์ R2–R3 ทั้งสองกรณี แล้วดูว่าขั้นตอนต่างกันตรงไหน

วิธีทำให้เร็วในห้องสอบFast method: one table, two passes

ตีตารางหนึ่งตาราง ไล่สองรอบ รอบแรกหา FD ทุกทางแล้ววงตัวที่ต่ำสุด รอบสองเอา RD ของทางที่เหลือมาเทียบกับตัวที่วงไว้

  1. ทำตาราง: ทาง (ชื่อเพื่อนบ้าน) | [[rd|RD]] | [[cost]] | [[fd|FD]] | FS?
  2. FD = cost + RD ทุกแถว (ถ้าโจทย์ให้ FD มาแล้ว ข้ามขั้นนี้)
  3. วง FD ที่ต่ำที่สุด แถวนั้นคือ [[successor]] และตัวเลขนี้คือ FD ของเส้นทาง
  4. แถวที่เหลือดูแค่ช่อง RD: ถ้า RD < ตัวที่วงไว้ เป็น [[fs|FS]] ถ้ามากกว่าหรือเท่ากัน ไม่เป็น
  5. เขียนคำตอบเป็น [[nexthop]] และ [[exitif]] ของ successor และ FS
