Security protocols & NAT

ข้อสอบจะเอาตาราง [[osi|OSI]] กับ security protocol จากสไลด์มาถามว่า protocol แต่ละตัวอยู่ชั้นไหน ป้องกันอะไร และข้อดีข้อเสียของแต่ละตัวคืออะไร อีกเรื่องคือ [[nat|NAT]] ทั้งสามแบบแปลงที่อยู่ยังไง บทนี้ไล่จากชั้นบนลงชั้นล่าง แล้วจบด้วยตารางเทียบข้อดีข้อเสีย

HTTPS คือ HTTP ที่ห่อด้วย SSL/TLSApplication layer: HTTPS, SSH, PGP, S/MIME

[[http|HTTP]] ส่งทุกอย่างเป็นข้อความธรรมดาผ่าน port 80 ใครดักได้ก็อ่านได้ [[https|HTTPS]] คือ HTTP ที่วิ่งผ่าน [[ssl|SSL]] / [[tls|TLS]] ข้อมูลระหว่าง browser กับ web server จึงถูกเข้ารหัส และใช้ port 443

ลองสลับดูว่าคนที่ดักอยู่กลางทาง (การโจมตีแบบ Sniffing จาก บทที่ 6) เห็นอะไรในแต่ละแบบ

web server ต้องติดตั้ง [[cert]] ที่ [[ca|CA]] ซึ่ง browser เชื่อถือเป็นผู้รับรอง (มีทั้งแบบฟรีและเสียเงิน) certificate นี้คือสิ่งที่ทำให้ HTTPS กัน Spoofing ได้ด้วย เพราะเว็บปลอมไม่มี certificate ที่ CA รับรองชื่อโดเมนจริง

ชั้นเดียวกันในตารางยังมี [[ssh|SSH]] (remote login แบบเข้ารหัส ใช้แทน Telnet), [[pgp|PGP]] และ [[smime|S/MIME]] (เข้ารหัสอีเมล) ทุกตัวในชั้นนี้ปกป้องแค่ application ของตัวเอง

SSL/TLS ตกลงกุญแจก่อนส่งข้อมูลSession/Transport layer: SSL handshake

application ที่ใช้ TCP เรียกใช้ SSL/TLS ได้ เพื่อให้ client กับ server ได้ [[authn]], [[conf]] และ [[integ]] ก่อนส่งข้อมูลจริง ทั้งสองฝั่งทำ [[handshake]] กันก่อน

ลากแถบเวลาดูทีละขั้นตามรูปในสไลด์ ขั้น 1 ถึง 2 คือการพิสูจน์ตัวตนของ server ขั้น 3 ถึง 4 คือการตกลงกุญแจ หลังจากนั้นข้อมูลทั้งหมดถูกเข้ารหัสด้วย [[sesskey]]

ทำไมต้องใช้สองแบบ: [[pubkey]] ปลอดภัยพอที่จะส่งผ่านเครือข่ายได้แต่ช้า จึงใช้แค่ตอนส่ง session key ส่วน session key เป็น symmetric key (key เดียวทั้งเข้าและถอด) ทำงานเร็ว จึงใช้กับข้อมูลทั้งหมด

สไลด์บอกว่า SSL/TLS ทำงานระหว่างชั้น Transport กับ Application และใช้กับ application protocol อื่นได้ด้วย เช่น IMAP, POP3, FTP ในตาราง p.20 จึงวาง SSL | TLS ไว้ที่ชั้น 5 ถึง 4

VPN ขุดอุโมงค์เข้ารหัสผ่าน InternetVPN: Remote-Access, Site-to-Site (Intranet, Extranet)

[[vpn|VPN]] สร้างเครือข่ายส่วนตัวบนเครือข่ายสาธารณะ ข้อมูลถูกเข้ารหัสแล้วห่อไว้ใน [[tunnel|อุโมงค์]] ฝั่งผู้ใช้เห็นเหมือนต่อสายตรงเข้าเครือข่ายในองค์กร

สไลด์แบ่งตามการใช้งานเป็นสองแบบ [[ravpn]] คือพนักงานคนเดียวต่อเข้าบริษัทจากบ้าน ส่วน [[s2svpn]] คือ gateway ของสองเครือข่ายต่อกัน แยกย่อยเป็น Intranet VPN (สำนักงานใหญ่กับสาขาขององค์กรเดียวกัน) และ Extranet VPN (ระหว่างองค์กรกับคู่ค้า)

โปรโตคอลที่ใช้ทำ VPN ตามสไลด์: [[pptp|PPTP]], [[l2f|L2F]], [[l2tp|L2TP]] ซึ่งอยู่ชั้น Data Link และ [[ipsec|IPSec]] ซึ่งอยู่ชั้น Network สไลด์หน้า VPN ตั้งชื่อว่า Network Layer เพราะ VPN สมัยนี้ส่วนใหญ่ใช้ IPSec

IPSec: เข้ารหัสแค่ข้อมูล หรือทั้ง packetNetwork layer: IPSec transport mode vs tunneling mode

[[ipsec|IPSec]] ปกป้องที่ชั้น Network ให้ทั้ง Confidentiality, Integrity และ Authentication มีสองโหมด ต่างกันที่ว่า IP header เดิมถูกเข้ารหัสด้วยหรือไม่

เลือกโหมดแล้วลากแถบเวลา จะเห็น packet ถูกสร้างทีละชั้นแบบเดียวกับรูปในสไลด์ แถวสุดท้ายคือสิ่งที่วิ่งอยู่บนสาย

[[transport]] ใช้แบบ host-to-host ทั้งสองเครื่องต้องรัน IPSec เอง IP header เดิมอยู่ข้างนอกไม่ถูกเข้ารหัส จึงเกิด [[traffic]] ได้ [[tunnelmode]] ให้ gateway เข้ารหัสแทน host ทั้ง packet ถูกซ่อนแล้วใส่ header ใหม่ของ gateway คนกลางรู้แค่ว่า gateway สองตัวคุยกัน

ข้อดีข้อเสียของแต่ละตัวAdvantages and disadvantages, side by side

หลักใหญ่ข้อเดียว: protocol ยิ่งอยู่ชั้นสูง ยิ่งป้องกันเฉพาะ application นั้นและต้องตั้งค่าที่แต่ละ app ยิ่งอยู่ชั้นต่ำ ยิ่งป้องกันทุก traffic ที่ผ่าน โดย app ไม่ต้องรู้ตัว แต่ต้องตั้งค่าที่เครื่องหรือ gateway และมี overhead

เลือก protocol สองตัวเพื่อเทียบกัน ข้อที่มาจากสไลด์ตรงๆ ขีดเส้นใต้ไว้ ที่เหลือเป็นเหตุผลที่ตามมาจากการทำงานของมัน

NAT แปลง IP ภายในก่อนออก InternetStatic NAT, Dynamic NAT, NAPT / PAT

เครื่องในองค์กรใช้ [[privip]] ซึ่งออก Internet ตรงๆ ไม่ได้ router ที่ทำ [[nat|NAT]] จึงเปลี่ยน IP ต้นทางเป็น [[pubip]] ก่อนส่งออก แล้วจดคู่ไว้ในตาราง พอคำตอบกลับมาก็แปลงกลับ

ช่วง private IP: 10.0.0.0 – 10.255.255.255, 172.16.0.0 – 172.31.255.255, 192.168.0.0 – 192.168.255.255 (สไลด์พิมพ์ช่วงกลางเป็น 172.32.255.255 ซึ่งผิด ที่ถูกคือ 172.31.255.255)

แตะส่งจากแต่ละเครื่องแล้วดูตารางแปลงที่อยู่ใน router ค่อยๆ เติม ใช้ตัวเลขเดียวกับสไลด์ ลองเทียบสามแบบ: [[staticnat]] จับคู่ 1 ต่อ 1 ตายตัว, [[dynnat]] สุ่มจาก pool, [[pat]] ใช้ IP เดียวแล้วแยกด้วย [[port]]
