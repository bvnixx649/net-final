RIP

อาจารย์จะถาม [[rip]] แบบละเอียด แต่ถามให้อธิบายการทำงาน ไม่ได้ให้ท่องรายการ: ดูรูปแล้วนับ [[hopcount|hop]], บอกว่าทางไหนดีที่สุด, เติม routing table ของ router ตัวหนึ่ง (วง, ขาออก, hop) และอธิบายว่าตารางค่อยๆ เต็มด้วย [[ripupdate|update ทุก 30 วินาที]] จนถึง [[convergence]] ได้ยังไง ไม่มีการคำนวณ IP

Metric ของ RIP คือการนับ routerHop count, maximum 15

[[hopcount]] ของวงหนึ่งคือจำนวน router ที่แพ็กเก็ตต้องผ่านต่อจากเราจนถึง router ที่ต่อกับวงนั้น วงที่ต่อกับเราตรงๆ เป็น 0 hop วงที่ต่อกับเพื่อนบ้านเป็น 1 hop RIP นับได้สูงสุด 15 ส่วน [[unreach|16 แปลว่าไปไม่ถึง]]

ในรูปบนสุด แตะชื่อวงแต่ละวง แล้วดูตัวเลขที่ขึ้นข้าง router ทุกตัว เช่น 10.4.0.0 ต่ออยู่กับ R3 จึงเป็น 0 hop สำหรับ R3, R2 ต้องผ่าน R3 อีกหนึ่งตัวจึงเป็น 1 และ R1 ต้องผ่าน R2 กับ R3 จึงเป็น 2

RIP ไม่สนใจความเร็วของลิงก์เลย นับแค่จำนวน router เพราะนับง่ายแบบนี้ จึงมีขีดจำกัด ลองยืดสายให้ยาวขึ้นแล้วดูว่า router ตัวสุดท้ายเห็นวงทางซ้ายสุดไกลกี่ hop

ตารางค่อยๆ เต็มทีละรอบCold start, exchange, convergence

ตอน [[coldstart]] router รู้แค่วงที่ต่อตรง (0 hop) จากนั้นทุกรอบ update แต่ละตัวส่งตารางทั้งตารางให้เพื่อนบ้าน ผู้รับ [[plusone|บวก 1 แล้วเก็บตัวที่น้อยกว่า]] พร้อมจดขาที่ข้อมูลเข้ามา ทำซ้ำจนไม่มีอะไรใหม่ คือ [[convergence]]

ลากแถบเวลาดูทีละจังหวะ เป็นตัวอย่างเดียวกับสไลด์ ช่องข้อความเหนือตารางแสดงว่า router ได้อะไรมาจากเพื่อนบ้าน บวก 1 แล้วได้เท่าไร และเก็บหรือไม่เก็บ

คอลัมน์ Interface ในตารางของสไลด์คือขาที่ update เข้ามา ซึ่งก็คือขาที่ต้องส่งแพ็กเก็ตออกไปหาวงนั้น บน router จริง show ip route จะแสดงบรรทัดเดียวกันนี้เป็น R 10.4.0.0/16 [120/2] via (IP ของ R2), Serial0/0/0 คือ [[ad|AD 120]] และ hop 2

ข้อความที่ส่งไปมาใช้กฎ [[splith]] ด้วย คือไม่บอกเส้นทางย้อนกลับไปทางที่ได้มา สังเกตในรอบที่ 2 R2 ไม่บอก 10.1.0.0 กลับไปให้ R1 เพราะได้มาจาก R1 เอง

ส่งทั้งตารางทุก 30 วินาทีPeriodic full-table updates and timers

RIP ไม่รอให้มีอะไรเปลี่ยน ทุก 30 วินาทีมันส่ง [[ripupdate|ตารางทั้งตาราง]] ให้เพื่อนบ้านซ้ำไปเรื่อยๆ การได้ยินซ้ำทุก 30 วินาทีคือวิธีที่ router รู้ว่าเส้นทางยังใช้ได้

รูปนี้ดูจากมุมของ R2 ช่องสุดท้ายของตารางคือเวลาที่ผ่านไปตั้งแต่ได้ยินเส้นทางนั้นครั้งล่าสุด ลองสลับเป็นแบบที่ R3 หยุดส่งไปเฉยๆ แล้วลากเวลาไปจนสุด

ตัวเลข 180 และ 240 วินาทีไม่มีในสไลด์ เป็น [[timers]] มาตรฐานของ Cisco ใส่ไว้ให้เห็นว่าถ้าเส้นทางหายไปเงียบๆ RIP ต้องรอหลายนาทีกว่าจะรู้ตัว สิ่งที่ต้องจำสำหรับข้อสอบคือ update ทุก 30 วินาที ส่งทั้งตาราง ไปหาเพื่อนบ้านที่ต่อตรง

ทำไม RIP converge ช้าConvergence time

ข่าวเรื่องวงใหม่เดินทางได้แค่หนึ่ง router ต่อหนึ่งรอบ update สายที่มี n router จึงต้องใช้ประมาณ n − 1 รอบ หรือ (n − 1) × 30 วินาทีกว่าทุกตัวจะรู้ครบ ยิ่งเครือข่ายใหญ่ยิ่งช้า

เลือกความยาวของสาย แล้วกดเล่นเพื่อดูข่าวเรื่องวง 10.1.0.0 ทางซ้ายสุดค่อยๆ ไหลไปทางขวา

สรุปเหตุผลที่ RIP ช้าและไม่เหมาะกับเครือข่ายใหญ่: ข้อมูลเดินทีละ hop ต่อรอบ, รอบละ 30 วินาที, ส่งทั้งตารางทุกรอบแม้ไม่มีอะไรเปลี่ยนจึงเปลือง bandwidth, ไปได้ไกลสุดแค่ 15 hop และเลือกทางจากจำนวน router โดยไม่ดูความเร็วลิงก์ เทียบกับ OSPF ที่ส่ง update ทันทีเฉพาะตอนมีการเปลี่ยนแปลงจึงเร็วกว่ามาก

ในสไลด์มีวิธีกันลูปของ RIP แค่ [[splith]] ตำราทั่วไปยังมีวิธีเสริมอีกหลายอย่าง เช่น route poisoning (ประกาศวงที่ล่มเป็น 16 ทันที), poison reverse, holddown timer และ triggered update (ส่งทันทีเมื่อมีการเปลี่ยนแปลง) ส่วนนี้ไม่มีในสไลด์ รู้ชื่อไว้ก็พอ

RIPv1 กับ RIPv2Classful vs classless RIP

ทั้งสองรุ่นนับ hop เหมือนกัน (สูงสุด 15) และส่งทุก 30 วินาทีเหมือนกัน ต่างกันที่ [[ripv1]] ส่งแบบ broadcast และไม่บอก subnet mask ส่วน [[ripv2]] ส่งแบบ multicast และบอก mask มาด้วย จึงใช้ VLSM ได้

คำสั่งตั้งค่า RIProuter rip, version 2, network

เปิด RIP ด้วย router rip เลือกรุ่นด้วย version 2 แล้วบอกด้วย [[ripnet|network]] ว่าขาไหนรัน RIP router จะหาเพื่อนบ้านและแลกตารางกันเอง ไม่ต้องพิมพ์เส้นทางทีละวงแบบ static

ตัวอย่างนี้คือ Router_A ในแล็บ 6 แตะแต่ละบรรทัดเพื่อดูว่าทำอะไร

สไลด์เขียน Router(config)#version 2 แต่ที่ถูกต้องพิมพ์ในโหมด Router(config-router)# หลัง router rip ตามที่แล็บเขียนว่า ver 2 ฝั่ง IPv6 ในแล็บใช้ ipv6 unicast-routing แล้วพิมพ์ ipv6 rip 10 enable ที่ทุก interface

โจทย์รูป Router A, B, C ในสไลด์Which direction does RIP choose?

RIP เลือกทางที่ผ่าน router น้อยที่สุดเสมอ ถึงทางนั้นจะใช้สายที่ช้ากว่า ความเร็วที่เขียนบนลิงก์ในรูปมีไว้หลอกให้คิดผิด

รูปจากสไลด์: Router A ต่อ B ด้วยสาย 56 Kbps, A ต่อ C และ C ต่อ B ด้วยสาย 1.5 (สไลด์เขียน Kbps ซึ่งน่าจะหมายถึง 1.5 Mbps) เครือข่าย B ต่ออยู่ที่ Router B เลือกว่าส่งจาก router ไหน
