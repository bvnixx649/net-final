ภัยคุกคามและ CIA

ข้อสอบจะให้ชื่อการโจมตี หรือให้รูปการโจมตีมาหนึ่งรูป แล้วถามว่าเป็นการโจมตีแบบไหน เป็น passive หรือ active และทำให้ [[conf]], [[integ]] หรือ [[avail]] ข้อไหนเสีย ต้องอธิบายเป็นคำพูดว่าเสียเพราะอะไร เช่น DoS ทำให้ Availability เสีย เพราะ server ถูกใช้ทรัพยากรจนผู้ใช้ที่มีสิทธิ์เข้าใช้ไม่ได้

สามสิ่งที่ต้องรักษาไว้CIA: Confidentiality, Integrity, Availability

ความปลอดภัยของข้อมูลวัดจากสามข้อ: [[conf]] คนไม่มีสิทธิ์อ่านไม่ได้, [[integ]] คนไม่มีสิทธิ์แก้ไม่ได้, [[avail]] คนมีสิทธิ์ต้องใช้ได้ทุกเมื่อ การโจมตีทุกแบบทำให้อย่างน้อยหนึ่งข้อเสียไป

ตัวอย่างด้านล่าง Bob ส่งคำสั่งโอนเงิน 500 บาทผ่านเครือข่ายไปที่ธนาคาร ลองทำให้เสียทีละข้อ แล้วสังเกตว่าแต่ละข้อเสียต่างกันยังไง ประโยคใต้ภาพคือสิ่งที่ควรเขียนในกระดาษคำตอบ

สังเกตว่าตอน C เสีย ธนาคารยังได้ข้อมูลครบและถูกต้อง (I กับ A ยังดี) แต่ข้อมูลรั่วไปแล้ว ส่วนตอน A เสีย ไม่มีใครเห็นหรือแก้ข้อมูลเลย แค่ใช้งานไม่ได้ เวลาตอบให้แยกให้ชัดว่าข้อไหนเสียและข้อไหนไม่เสีย

สไลด์บอกวิธีรักษาแต่ละข้อไว้ด้วย: C ใช้ [[encrypt]] และ [[authn]] / [[authz]], I ใช้ [[hash]], A ใช้การ update patch, ระบบที่ทำงานได้ 24 ชั่วโมง 7 วัน (Reliability) และออกแบบเครือข่ายให้พอกับจำนวนผู้ใช้

ความเสี่ยงเกิดจากสองอย่างมาเจอกันRisk = Vulnerability + Threat

สไลด์นิยาม [[risk]] ว่ามาจาก [[vuln]] (ช่องทางที่เจาะเข้าระบบได้) และ [[threat]] (สิ่งภายนอกที่อาจมาทำความเสียหาย) เมื่อภัยคุกคามใช้ช่องโหว่ได้จริง จึงเกิด [[attack]]

ลองเปิดปิดสองอย่างนี้ดู ช่องโหว่ในตัวอย่างคือ server ที่ยังไม่ update patch ภัยคุกคามคือ cracker ที่กำลังหาช่องทางเข้า

ช่องโหว่ที่สไลด์ยกตัวอย่าง: การจัดการบัญชีผู้ใช้ไม่ดี (คนย้ายแผนกหรือลาออกแล้วสิทธิ์ยังเหมือนเดิม), software bugs, ไม่ update patch, ไม่ update anti-virus

ภัยคุกคามมีสามส่วน

สไลด์แยกภัยคุกคามเป็น [[target]] (จะทำลายข้อไหนของ CIA), [[agent]] (ใคร ต้องมี Access, Knowledge, Motivation) และ [[event]] (เกิดอะไรขึ้น) ดูตัวอย่างกับพนักงานที่ลาออกแล้วแต่บัญชียังไม่ถูกปิด

ประเภทของภัยคุกคาม

สไลด์แบ่งภัยคุกคามไว้ 12 ประเภท เลือกตัวอักษรเพื่อดูว่าประเภทไหนมักทำให้ข้อนั้นเสีย (สไลด์ไม่ได้จับคู่กับ CIA ไว้ ตัวอักษรท้ายแถวคือข้อที่โดนกระทบชัดที่สุด ใช้ช่วยคิดเวลาเขียนตอบ)

อ่านรูปการโจมตีให้ออกAttack approach: Snooping, Modification, Spoofing, DoS

รูปในข้อสอบมาจากสไลด์ ตัวละครเดิมทุกรูป: Bob ส่ง Alice รับ Darth คือผู้โจมตี สิ่งที่บอกว่าเป็นการโจมตีแบบไหนคือ หัวลูกศรไปจบที่ใคร

ก่อนดูรูป แยกการโจมตีเป็นสองแบบ: [[passive]] ผู้โจมตีแค่ดูหรือฟัง ไม่เปลี่ยนข้อมูล กับ [[active]] ผู้โจมตีแก้ ปลอม หรือขัดขวาง แบบ passive ตรวจจับยากเพราะข้อมูลยังถึงปลายทางครบ

รูปด้านล่างมี 4 รูปตามสไลด์ เลือกรูป กดเล่นหรือลากแถบเวลา แล้วตอบว่าเป็นการโจมตีอะไรและทำให้ข้อไหนของ CIA เสีย จากนั้นเทียบกับคำตอบตัวอย่าง

วิธีจำ: ลูกศรเดิมยังถึง Alice และมีเส้นแยกไป Darth = [[sniff]] (C เสีย) ลูกศรของ Bob ไปจบที่ Darth แล้ว Darth ส่งเส้นใหม่ไป Alice = [[modify]] (I และ C เสีย) มีแต่ลูกศรจาก Darth ไป Alice = [[spoof]] หลายเครื่องรุมยิงไปที่ server เครื่องเดียว = [[dos]] (A เสีย)

การโจมตีอื่นในรายการ และป้องกันด้วยอะไรOther attacks listed on the slide

สไลด์ Attack Approach ให้รายชื่อการโจมตีอีกหลายแบบแต่ไม่มีรูป ข้อสอบถามได้แบบ "การโจมตีนี้กระทบ CIA ข้อไหน" ใช้หลักเดิม: ข้อมูลรั่ว = C, ข้อมูลถูกแก้ = I, ใช้งานไม่ได้ = A

การป้องกันแบ่งได้สองกลุ่ม การโจมตีที่อ่านหรือแก้ข้อมูลระหว่างทาง (Sniffing, Modification) ต้องแก้ด้วยการเข้ารหัสและ hash ซึ่งเป็นงานของ security protocol ใน บทที่ 8 ส่วนการโจมตีที่ต้องส่ง packet เข้ามาในเครือข่าย (DoS, worm, การลอบเข้า port ที่ไม่ได้ใช้) [[firewall]] ช่วยกรองได้ ประเภทของ firewall และว่าแต่ละแบบกันอะไรได้อยู่ใน บทที่ 7

ใครเป็นคนโจมตีAttacker

สไลด์แบ่ง [[attacker]] ตามระดับความชำนาญกับแรงจูงใจ คู่ที่ถามบ่อยคือ Hacker กับ Cracker ซึ่งชำนาญสูงเท่ากัน ต่างกันแค่แรงจูงใจ

Malware แพร่และทำลายต่างกันVirus, Worm, Trojan horse, Backdoor

[[malware]] คือโปรแกรมที่มุ่งร้าย สิ่งที่ข้อสอบใช้แยกแต่ละแบบคือ ต้องอาศัยไฟล์อื่นไหม, แพร่ตัวเองได้ไหม และทำให้ CIA ข้อไหนเสีย

เลือกชนิด แล้วเล่นดูในเครือข่าย 6 เครื่องเดียวกัน [[virus]] ต้องรอให้คนเปิดไฟล์ [[worm]] แพร่ไปเองผ่านเครือข่าย [[trojan]] ปลอมตัวเป็นโปรแกรมดีแต่ไม่แพร่ [[backdoor]] คือทางลับที่ข้ามการ login

ในรายการ malware ของสไลด์ยังมี [[logicbomb]] และ [[zombie]] ซึ่งให้แค่ชื่อ zombie คือเครื่องแบบเดียวกับ 5 เครื่องในรูป DDoS
