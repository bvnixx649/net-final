Router เลือกทางยังไง

ส่วนนี้ไม่มีการคำนวณ IP ข้อสอบจะให้รูปหรือรายละเอียดมา แล้วถามว่า [[router]] ทำอะไรกับแพ็กเก็ตที่เข้ามา ([[flow|decision flow]]), อ่านบรรทัดใน [[rtable]] ออกไหม, static, RIP, EIGRP, OSPF เป็นแบบไหนและใช้ [[metric]] อะไร และถ้ามีหลายแหล่งบอกทางไปที่เดียวกัน router จะเชื่อใคร ซึ่งตัดสินด้วย [[ad]]

Router ทำสองอย่าง: เลือกทาง แล้วส่งต่อTwo functions of a router

[[router]] ต่อหลายเครือข่ายเข้าด้วยกัน งานของมันมีสองอย่าง คือหาว่าแพ็กเก็ตควรไปทางไหน แล้วส่งต่อออกไป ทั้งสองอย่างดูจาก [[rtable]] ของตัวเองเท่านั้น

[[iface]] แต่ละขาของ router ต่อกับเครือข่ายคนละวง และมี IP ที่อยู่ในวงนั้น พอตั้ง IP แล้วเปิดขานั้น router รู้จักวงนั้นทันที และเพิ่มสองบรรทัดลงตาราง คือ [[connected|C]] วงที่ต่ออยู่ กับ [[local|L]] IP ของขานั้นเอง ลองแตะแต่ละขาของ R1

สไลด์สรุปหลักของ routing table ไว้ 3 ข้อ ซึ่งเห็นได้จากรูปบนสุดของหน้า:

  1. router แต่ละตัวตัดสินใจเองคนเดียว จากข้อมูลในตารางของตัวเองเท่านั้น
  2. ตารางของ router ตัวหนึ่ง ไม่จำเป็นต้องเหมือนของอีกตัว (R1 กับ R2 มีบรรทัดไม่เหมือนกัน)
  3. รู้ทางไปไม่ได้แปลว่ารู้ทางกลับ R1 มีทางไป 192.168.2.0/24 ไม่ได้แปลว่า R2 มีทางกลับมา 192.168.1.0/24 ต้องตั้งที่ R2 แยกอีกที

แพ็กเก็ตเข้ามาแล้วไปไหนPacket forwarding decision process

แพ็กเก็ตเข้ามาเป็นบิตที่ [[layers|Layer 1]] router [[encap|แกะ]]ขึ้นไปถึง Layer 3 เพื่ออ่าน [[destip]] แล้วหาใน [[rtable]] ด้วย [[lpm]] เจอแล้วห่อกลับลงมาส่งออก [[exitif]] ถ้าไม่เจอเลยก็ [[drop|ทิ้ง]]

เลือกปลายทางแล้วลากแถบเวลาดูทีละจุด ลองให้ครบทั้งสามแบบ เพราะคำตอบในข้อสอบต้องบอกผลให้ครบ: ปลายทางอยู่ใน [[connected|วงที่ต่อตรง]], อยู่วงไกลต้องส่งให้ [[nexthop]], และไม่มี entry ไหนตรงเลย

ตอนเทียบกับตาราง router ดูว่า IP ปลายทางตกอยู่ในวงไหนบ้าง ถ้าตรงหลายบรรทัด ให้เอาบรรทัดที่ prefix ยาวที่สุด ลองเปิด [[defroute]] แล้วส่งไป 192.168.2.20 จะเห็นว่าตรงทั้ง /24 และ /0 router เลือก /24 เพราะเจาะจงกว่า default route จึงถูกใช้เฉพาะตอนที่ไม่มีอย่างอื่นตรงเลย

ถ้าข้อสอบถามว่าแพ็กเก็ตเข้ามาแล้ว router ทำอะไร เขียนตามลำดับนี้:

  1. รับบิตเข้ามาทาง interface แล้วประกอบเป็นเฟรม (Layer 1 → Layer 2)
  2. แกะ header และ trailer ของ Layer 2 ออก อ่าน IP ปลายทางใน IP header (Layer 3)
  3. หา entry ใน routing table ที่ตรงกับ IP ปลายทางยาวที่สุด
  4. ถ้าเป็นวงที่ต่อตรง ส่งถึงเครื่องปลายทางเลย ถ้าเป็นวงไกล ส่งให้ next hop โดยห่อเฟรมใหม่แล้วส่งออก exit interface
  5. ถ้าไม่มี entry ไหนตรงและไม่มี default route ทิ้งแพ็กเก็ต

อ่านบรรทัดใน routing tableshow ip route

หนึ่งบรรทัดของ show ip route บอกครบว่าเส้นทางนี้ได้มาจากไหน ([[code]]) ไปวงอะไร ([[network]]) น่าเชื่อแค่ไหน ([[ad]]) ไกลแค่ไหน ([[metric]]) ส่งให้ใคร ([[nexthop]]) และออกขาไหน ([[exitif]])

แตะแต่ละช่องเพื่อดูความหมาย แล้วสลับตัวอย่างดูว่าแต่ละแหล่งหน้าตาต่างกันยังไง บรรทัด O, D, S, C, L มาจากสไลด์ ส่วนบรรทัด R คิดจาก topology ของแล็บ 6

Static ให้คนกำหนด Dynamic ให้ router คุยกันเองStatic vs dynamic routing

[[static]] คือเส้นทางที่ผู้ดูแลพิมพ์เองทีละวง ส่วน [[dynamic]] ให้ router แลกข้อมูลกันเอง เพื่อค้นหาวงที่อยู่ไกลและหาทางใหม่เมื่อทางเดิมใช้ไม่ได้

รูปนี้คือ topology ของแล็บ 6 แตะแต่ละส่วนของคำสั่งเพื่อดูว่ามาจากตรงไหนในรูป แล้วแตะลิงก์ A–B เพื่อตัดสาย เทียบกันระหว่าง static กับ dynamic ลิงก์ A–C เป็นสายที่แล็บเพิ่มในการทดลองที่ 2

สไลด์บอกว่า static เหมาะกับเครือข่ายเล็ก ดูแลง่าย, [[stub]], ทำ [[defroute]] และเส้นทางเฉพาะบางวง ส่วน dynamic เหมาะกับเครือข่ายใหญ่ที่เปลี่ยนบ่อย และต้องค้นหาวงที่อยู่ไกลเอง

ทุกตัวที่ออกสอบเป็น interiorIGP vs EGP

[[igp]] หาเส้นทางภายใน [[as]] เดียว [[egp]] หาเส้นทางระหว่าง AS static, RIP, EIGRP และ OSPF ที่เรียนมาเป็น interior ทั้งหมด ตัว exterior ในสไลด์มีแค่ [[bgp]]

เลือกโปรโตคอลเพื่อดูว่ามันทำงานอยู่ตรงไหนของรูป

Distance vector รู้แค่ทาง Link state เห็นทั้งแผนที่Distance vector vs link state

dynamic protocol แบ่งตามวิธีทำงานได้สองแบบ [[dv]] เชื่อสิ่งที่เพื่อนบ้านบอก รู้แค่ระยะกับทิศ ส่วน [[ls]] ให้ทุกตัวมีแผนที่ทั้งเครือข่ายแล้วคำนวณเอง [[rip]] เป็น DV, [[ospf]] เป็น LS, [[eigrp]] อยู่ตรงกลางแต่ใกล้ DV

เลือกโหมด แล้วแตะ router อีกตัวเพื่อเปลี่ยนมุมมอง ดูว่าแต่ละตัวรู้อะไรบ้าง และส่งอะไรให้กัน

EIGRP ส่งข้อมูลให้เพื่อนบ้านแบบ distance vector จึงยังไม่เห็นแผนที่ทั้งหมด แต่เก็บเส้นทางที่เพื่อนบ้านทุกตัวบอกไว้ใน topology table เพื่อมีทางสำรองพร้อมใช้ ส่วนนี้คล้าย link state เล็กน้อย

[[metric]] คือตัวเลขที่โปรโตคอลใช้เทียบเส้นทาง ยิ่งน้อยยิ่งดี RIP นับ [[hopcount]], OSPF ใช้ [[ospfcost]] ที่คิดจาก bandwidth, EIGRP ใช้ [[eigrpmetric]] จาก bandwidth กับ delay ทางเดียวกันจึงอาจถูกเลือกต่างกัน
